How it works: We record every token's expert selection from the Qwen model (pretrained or LoRA-finetuned) — which experts are co-activated, and on which ranks. This builds an affinity graph (rank-pair communication matrix). The top-k highest-affinity rank pairs are pre-configured as OCS circuits before inference starts. At inference time, these circuits are already established — no runtime reconfiguration penalty. The result: OCS pre-set hides circuit setup latency under the known affinity pattern.

Training Affinity — Rank-Pair Communication

How to read: Cell (Ri, Rj) shows communication frequency between rank i and rank j, derived from expert co-activation in the Qwen model routing trace. This is the affinity graph that drives OCS circuit pre-configuration. Darker cells = more co-activation = higher priority for pre-set circuits. Dashed green outlines show preset circuits.

OCS Pre-set — Circuit Coverage

How to read: Green bars = rank pairs covered by OCS pre-set circuits (derived from training affinity). Red bars = rank pairs NOT covered. High green coverage = pre-set circuits are well-placed for the actual inference traffic.

Expert Load Distribution

How to read: Which experts are most frequently selected. Blue = training (affinity source), orange = inference. Similar heights = stable expert preference across train/infer. Divergence = preference shift.

Per-Layer Routing Consistency (JS Divergence)

How to read: Each bar is one MoE layer. Low JS divergence (< 0.1, green) = training/inference routing nearly identical — pre-set circuits should work well. High divergence (> 0.3, red) = routing patterns differ — pre-set may need adjustment for that layer.
